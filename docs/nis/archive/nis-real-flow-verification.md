# NIS Real-Flow Verification

## Current Candidate Source Truth
**Classification: Option C (Frontend cannot reach backend and uses frontend mockCandidates).**

During the audit, we identified that the `GET /api/v1/nis/considered-few` endpoint was crashing with an `Internal Server Error` because the method `get_considered_few` was declared on the router but never implemented in `NISConsideredFewService`. 

Because of this crash, the frontend's explicit offline fallback was being triggered automatically, rendering the hardcoded `mockCandidates` and bypassing the backend entirely.

## How the NIS Pipeline Works
The NIS considered few pipeline processes candidates deterministically without Firebase or standard matching algorithms.
1. **NISHardFilterEngine**: Filters candidates for absolute dealbreakers (age bounds, verified status, location mismatch without relocation openness, conversation caps).
2. **NISCompatibilityEngine**: Assesses dimension scores across 10 traits, identifying `is_tension_point`, `is_dangerous_mismatch`, and `is_shared_strength`.
3. **NISConfidenceThresholdService**: Enforces system safety and rule blocks, only allowing a candidate if the final status is `HIGH_CONFIDENCE_MATCH`.
4. **NISConsideredFewService**: Packages the high-confidence candidates into secure DTOs, stripping out any PII, raw Raya evaluations, photos, or percentages.

## Fixes Applied
1. **Backend Route Fixed**: Implemented `NISConsideredFewService.get_considered_few()`. It now spins up a mock repository of users (to simulate DB records) and routes them through the full Hard Filter, Compatibility, and Confidence pipeline before returning.
2. **Frontend Enforced**: The frontend now safely connects to the backend and renders the *real* dynamically filtered candidates. If the backend returns `NO_SUITABLE_MATCHES_RIGHT_NOW`, the frontend correctly displays the empty state and does *not* replace it with mock candidates.

## Tests Added
Created `backend/app/nis/tests/test_nis_pipeline_verification.py` to deterministically verify the pipeline:
1. `test_pipeline_strong_candidate_passes`: Confirms a perfectly aligned candidate succeeds and returns `HIGH_CONFIDENCE_MATCH`.
2. `test_pipeline_hard_rejection_blocked`: Confirms a candidate under the minimum age preference is silently dropped.
3. `test_pipeline_weak_compatibility_blocked`: Confirms a candidate failing multiple dimensional traits (volatile, low family responsibility, etc.) is dropped.
4. `test_pipeline_privacy_fields_not_exposed`: Confirms the response strips `raw_raya`, percentages, swipe feeds, and PII.
5. `test_api_route_considered_few`: Hits the FastApi test client directly to ensure the route succeeds (200 OK) without exceptions.

## Remaining Gaps Before Production
- The mock repository in `NISConsideredFewService.get_considered_few()` needs to be replaced with a real database integration (e.g., SQLAlchemy fetching `User` and `MatchPreference` models).
- Raya text previews are currently static strings and need to be generated by the real `RayaScriptService` when live.
